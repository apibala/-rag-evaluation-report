RAG 知识库问答系统评测

从「能跑通」到「知道它什么时候会失败」

扣子（Coze）平台 · 真实官方文档语料 · 四轮对照实验

这不是一个"我搭了个知识库问答"的 Demo，而是一份"我把它的失败测出来了"的评测报告。 所有结论均基于实测，含两次被证伪的假设与一次语料污染复盘。

⚠️ 评测污染事件（已确认未生效）
2026-10-12 发现知识库混入第一轮《AI 入职第一周行动手册》，其第四节明文写着 "智能体必须回答'资料中没有提到这一点'"——等于把考试答案放进考试范围（Data Contamination）。 处理过程：定位 → 要求清理语料 → 误以为已清理（验证题仍答出）→ 发现未清理 → 真正删除 → 验证题确认干净 → 干净语料重跑陷阱题仍 3/3。 结论：污染确实存在，但未实际生效——拒答能力来自平台兜底 + 模型对齐，而非抄文档。

这个项目在做什么

大多数人做完 RAG 的终点是"能回答问题了"。这个项目的起点是：

它在什么情况下会答错？答错了之后我怎么知道是哪里错了？
实验类型目的结论
单变量对照实验定位检索失败根因锁定「词汇不匹配」
消融实验拆解防幻觉机制三层冗余，假设两次被证伪
双向验证测改进是否牺牲安全性有用性↑，安全性未退化
重复运行量化输出稳定性一致率 0，确立重复取样纪律

四条核心发现

1词汇不匹配是失败诱因之一，但不是主因

同一个知识点，只改提问措辞，其余条件全部相同。首次实测：口语版"可以发布给别人用吗"答不出，原文词"自定义插件"答对。

重跑（语料未变）后口语版也答对了，唯一真实变量是提示词 v1→v3。修正结论： 失败关键不在用户措辞，而在提示词是否允许模型复用已召回的片段 （v1 把"未完全匹配"等同于"没有信息"→错误拒答；v3 允许基于部分片段作答→成功）。

2防幻觉是三层冗余的（消融实验，假设两次被证伪）

层级机制结论
平台层检索兜底检索为空→系统返回"未查询到"✅ 主力防线，条件触发
提示词·角色设定"你是文档问答助手"✅ 生效
提示词·显式防幻觉约束"绝对不要编造"⚠️ 完全无召回场景下冗余

3"绝对不要编造"会以牺牲有用性为代价

v1 下部分召回的问题只得到一句干巴巴的"资料中没有提到这一点"。改成"说明缺什么 + 给出已有部分"（v2）后：

资料中仅提到可以为智能体添加开场白来增强对话体验，未说明具体设置步骤。可在编排页面左侧"人设与回复逻辑"面板中…可尝试在此处定义开场白。

双向验证：有用性显著提升，陷阱题仍 3/3 零编造。

4提示词只能引导倾向，不能保证行为

口径v2v3
明确标注率33%50%
给出推断比例67%75%

根因是两层随机性叠加：①模型要不要给推断 ②给了之后标不标注。由此提出改用结构化输出（v4）——用格式约束替代语义约束。

一个容易被误判的点：编造 ≠ 推断

表现用户后果
编造把不存在的内容当事实："在设置→高级选项中配置开场白"照做，然后失败
推断基于真实片段外推 + 标注不确定："可尝试在人设与回复逻辑面板中定义"知道要自己验证

上面的优质回答逐句核对后 4/5 分句都是原文照搬，只有最后一句是标注过的推断——第一眼很容易被误判成幻觉。

输出非确定性：被量化的一个发现

同一道题、同一份资料、同一个提示词，每题开新会话跑 3 次，三次回答内容一致率 0/3。

任何基于单次运行的评测结论都不可靠。一次通过不代表系统稳，一次失败也不代表系统有问题。必须重复取分布。

局限与未解决（如实列出）

  • 仅单一平台（扣子），未做跨平台横向对比（MaxKB 因 Docker、千帆因计费均未跑通）
  • 样本量偏小：陷阱题仅 3 道，重复运行 3–4 次，结论应视为定性
  • v4 方案未验证；检索层参数（Top-K / 阈值）未做参数扫描
  • 语料较小（约 3500 字），无法代表大规模知识库
  • 多因素未做正交分离：词汇匹配度、语料纯净度、提示词版本在重跑中同时变化。若要严格归因需 2×2×2 正交实验

复现方式

  1. 扣子平台新建智能体 → 挂 data/Coze官方文档资料集.txt 为知识库
  2. 提示词用 prompts/ 下任一版本
  3. 按 10 题测试集提问
  4. 每道题开新会话（连着问会污染结果）
把局限写清楚，比把结论说满更可信。这份报告的价值，一半在结论，一半在"我是怎么发现自己错了的"。
